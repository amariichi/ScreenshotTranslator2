# Ubuntu 学習モード

英語字幕・スマホのメッセージ・画面内の文章を、独立したGTKウィンドウで原文と日本語訳として読みます。同じ一つのアイコンに「従来モード」（Overlay/TTS）と「学習モード」をまとめています。このパネルはUbuntuのGNOME/GTK4向けで、実動確認はUbuntu 26.04.1・GNOME 50.1・Waylandです。Web/Windowsクライアントの翻訳経路も引き続き利用できます。

## 起動

既存のローカルllama.cpp（既定8009）とFastAPI（既定8012）を先に起動します。通常の `./start.sh` を使う場合は、従来どおり依存同期とTTS準備が実行されます。すでにサーバーが起動中なら再起動は不要です。ただし、この学習APIを追加する前から動いていたFastAPIには新しいルートがありません。

追加で必要な実行環境は既存システムの `gjs`、GTK4、Soup3、`glib-compile-schemas` です。下の学習用スクリプトはパッケージ・モデルのインストールやGNOME再起動を行いません。

```sh
./gnome-learning-extension/install.sh
gnome-extensions disable screenshot-translator@amariichi
gnome-extensions enable screenshot-translator-learning@amariichi
./start-learning.sh
```

有効にするUUIDは `screenshot-translator-learning@amariichi` 一つです。旧UUID `screenshot-translator@amariichi` のファイルと設定を残したまま無効にします。統合版は旧設定・ショートカットを引き継ぎ、従来モードも内部で提供します。インストーラーは以前の学習拡張があれば日時付きで退避します。旧UUIDが有効のまま統合版を有効にした場合も、旧側の停止を確認してから一つのアイコンを作ります。

拡張が「存在しない」と表示される場合や更新が反映されない場合は、通常のログアウト・再ログイン後に有効化してください。再ログイン後はバックエンドも起動し直します。パネルだけ開いても、拡張が未接続の間は画面取得できません。スクリプトがログアウト・GNOME再起動を自動で行うことはありません。

`start-learning.sh` はパネルだけを起動します。サーバーとの通信はローカルHTTP限定で、画像を外部APIへ送りません。学習機能だけのサーバーが必要な場合は、既存モデルサーバーに対して `.venv/bin/python -m uvicorn app.learning_app:app --host 127.0.0.1 --port 8012` も使えます。この専用サーバーには従来のTTS等のAPIはありません。

## 視聴する

統合アイコンの「学習モード」→「学習パネルを開く」でパネルを開けます。「従来モード」ではText Overlay/TTS Once/TTS Monitorを選択し、「取得範囲を選択…」または従来の `Ctrl+Alt+S` を使います。モード切り替え時は以前の取得を止めます。「すべての取得を停止」は両方を停止します。拡張の有効化・パネルを開く操作だけでは取得しません。

1. 「新規」で作品・エピソードごとの記録を作ります。「記録設定」で出典URL、場面のメモ、既知語を編集できます。既知語の初期値は `insecure` です。
2. パネルを動画の外へ移動し、「範囲を選ぶ」で字幕やメッセージの領域を選びます。選択終了から取得が始まります。選択はEscape/右クリックで取り消せます。
3. 「停止」「再開」で画面取得を操作します。動画そのものは操作しません。字幕とSMSなどは別ブロックに記録され、話者は画面で確認できる名前だけを使います。
4. 取得中は原文・訳・短い文脈と未処理状態を自動保存します。「停止」で取得を止めると未処理分の学習メモを自動生成し、進捗を表示します。動画の停止とは別です。難しい慣用表現・口語・非直訳表現等を選び、1項目につき最大2件の下書きを作ります。「再開」は解説の新規要求を止め、実行中の1要求の終了後に翻訳を優先します。未処理は次の取得停止後に継続します。起動や接続切れだけでは推論を開始しません。
5. 「学習メモ」の「メモを編集」で意味・文脈・語調・要確認状態を修正します。引用と出典IDは保持されます。「未処理を生成」は保留分のみ、「失敗分を再試行」は失敗分のみを処理します。対象表現がない字幕も処理済みです。失敗は自動再試行せず、要求が3組続けて失敗したら後続を未処理のまま保持して停止します。

パネルは通常のウィンドウとして移動・リサイズでき、次回も配置と選択中の記録を復元します。パネルやそのダイアログが取得範囲へ重なる、閉じる、最小化する、別ワークスペースへ移る場合は取得を停止します。接続を失った場合もバックエンドのリースが約15秒で失効します。停止後や世代の古い応答、取得から8秒を超えた応答は表示・記録しません。

## 保存

保存先はリポジトリ内のGit除外済み `.learning-data/` です。画像ファイルは保存しません。

- `history.sqlite3`: 原文、訳、取得時刻（UTC）、種別、話者、前の短い文脈、解説、編集状態。
- `日時-作品名-ID.md`: 原文・訳・学習メモをまとめた生成ファイル。

既存の `.user-notes.md` は保持しますが、新しい個人メモファイルは作成しません。

一番上の「記録」で作品ごとの記録を選びます。「操作」から「保存フォルダを開く」「名前を変更」「記録を削除」を選べます。改名しても保存ファイル名とIDは変わりません。削除は対象名の確認後、原文・訳・学習メモ・既存関連ファイルを `.learning-data/.trash/日時-ランダムID/` へ退避します。取得・生成中は削除できません。退避先の `record.json` に全データと元ファイル名があり、Markdownと既存個人メモも残ります。自動で完全削除しません。

退避した記録を完全削除するときは「操作」→「ゴミ箱を空にする…」を選び、件数と「復元できません」の警告を確認して「完全に削除」を押します。キャンセルが既定です。対象はこのアプリの `.learning-data/.trash/` 内の退避記録だけで、現在の記録は対象外です。空なら通知だけを表示します。取得・生成中、確認後に内容が変わった場合、想定外のファイルやリンクがある場合は削除せずに通知します。途中で失敗した場合は、既に完了した件数と一部削除の可能性を表示し、残りを確認し直す必要があります。

`.learning-data/` 全体（ゴミ箱、キャッシュ、生成Markdownを含む）は `.gitignore` の対象です。共有やバックアップの際は、原文と私的メモを含むことに注意してください。

「保存した記録を開く」で生成Markdownを開けます。直接編集は次の保存で更新されるため、学習メモの修正はパネルで行ってください。「保存を再試行」はDB/Markdown保存失敗後にも使えます。再起動しても履歴と編集済み解説は残り、取得は停止状態へ戻ります。中断中の項目は未処理に戻ります。

## 処理と確認範囲

1画像で原文と訳を取得し、同一画像は成功確認後だけスキップします。字幕は連続重複を、SMS等は同じ種別・話者・原文・画面内出現数の重複を抑制します。否定形・数字を落とす曖昧一致は使いません。動く背景では画像が変わるため、同じ字幕でも画像推論が必要です。モデルへ送る前の独立したOCRは追加していません。

モデルへの要求は同時に1件です。取得は0.5秒間隔で翻訳待ちと独立して行い、処理中に変わった画像は最新1枚だけ待機させます。さらに変化すると待機画像を置き換えるため、短い字幕をすべて回収できる保証はありません。停止・範囲・記録・接続先の変更で待機画像を破棄します。解説の未処理分はDBへ保存します。解説の選別は現在の原文だけを最大3項目ずつ与え、引用を検証してから対象の短い文脈説明を生成します。前4項目・後2項目のうち90秒以内の履歴と場面メモを参照し、長い中断をまたぐ文脈を避けます。入力上限を守るため解説対象は各原文の先頭1800文字、前後文脈は各300文字までです。本文全体は履歴に残ります。パネルの履歴表示は直近200項目で、以前の履歴はMarkdownから確認できます。

パネルは翻訳や状態の確定通知を受けて表示を更新します。選択中の記録に対して待機通信を1件だけ持ち、記録・接続先の変更やパネル終了で解除します。通知が使えない場合は従来の定期確認へ戻り、切断後は再接続します。ローカルモデルへのHTTP接続は翻訳と解説で再利用し、バックエンド終了時に閉じます。

引用は保存済み原文との一致を検査し、同一表現の解説は記録内で抑制します。ただし表記の異なる類義表現を意味で統合することはしません。同じ短文のSMSが後で新しく届いた場合や、同一字幕が画面を切り替えず再登場した場合は、画像だけでは新しい発話と区別できないことがあります。

モデルの意味理解・OCRは下書き品質です。否定、皮肉、俗語の意味選択、画面内の順序、話者は誤り得ます。`He's loaded` のような文脈不足の表現は断定を避けて確認してください。前後文脈なしの単独項目はモデルが確信を返しても「要確認」にします。引用確認は意味の正しさを保証しません。

全候補は引用文全体を指定した短い文脈説明を行います。否定を含む候補は、肯定形の辞書説明へ戻る失敗が実測されたため、追加で「要確認」にします。この再確認も同じモデルによる下書きです。否定・皮肉を含む文は特に原文を見て判断してください。

`maybe/perhaps` を含む原文が断定的に訳される例もあり、訳に代表的な推量表現が見つからない場合は確認表示を出します。この語形検査は翻訳全体の意味を検証するものではありません。既知語の設定変更は、未解析の項目と今後取得する項目に適用されます。

長時間の継続取得、倍率が異なる複数画面、GNOME 46〜49での実動確認は未実施です。動画の再生・停止は利用者が操作し、アプリが配信サイトの再生やダウンロードを自動操作することはありません。
